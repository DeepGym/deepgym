# Changelog

## Unreleased

- **Traces:** `dg.trace(env, AgentMeta(...))` records a graded episode while it runs, in a versioned, frozen schema (`deepgym.traces.Trace`, schema 1.0). It holds provenance (environment name, variant and seed; SHA-256 of the environment definition, task, verifiers and reference; the image digest when the image pins one; deepgym version; provider; the agent, model and sampling config you pass; timestamps), every step (the action, the model messages behind it with optional token ids and logprobs, the observation, the step reward with the step verifier's output, exit code, error) and the final `RunResult` with `has_verdict`. Each event is appended and flushed to `~/.deepgym/traces/<id>.jsonl` (or `$DEEPGYM_TRACES_DIR`) as it happens, so an exception or a killed process keeps the steps so far and the trace is marked `incomplete`. A traced episode refuses actions after `score()`, so its verdict always matches the state it ends in. `deepgym traces export --format jsonl|parquet|atif [--rows trace|rl] [--only-valid]` reads those files and the console database and writes whole traces, SFT/RL rows (`messages`, `reward`, `step_rewards`, for TRL and verl) or ATIF (Agent Trajectory Interchange Format) v1.7 documents. Traces without a verdict are flagged (`has_verdict: false`, null reward) or left out with `--only-valid`. Exports are strict JSON (a NaN in verifier output becomes null), and ATIF export refuses a non-empty directory so stale documents never mix in. Parquet needs the new `deepgym[traces]` extra (pyarrow). DeepGym now needs pydantic 2.7 or later. `record_episode` also accepts a trace and keeps it in a new `trace` column; existing databases gain the column on open, and plain trajectories record as before. `Session.step_verdict` exposes the last step verifier output and exit code; a step verifier that reports its own failure (exit 2, or an `error_type` that isn't the model's fault) leaves the trace's step reward null instead of 0. A NaN or infinite per-case `execution_time_ms` is now zeroed, since JSON can't carry it.
- **Axolotl: fake PRM data removed.** `generate_prm_dataset`, `results_to_prm_record`, `write_prm_dataset`, `PRMRecord` and `deepgym generate-prm` are gone. They relabelled a solution's per-test diagnostics ("Input: ... Expected: ... Got: ...") as reasoning steps with pass/fail labels, which is not process supervision. Real step-level rewards, from step verifiers in multi-turn episodes, are exported as `step_rewards` by `deepgym traces export --rows rl`. `generate_axolotl_config(method='prm')` stays, for stepwise data you bring.
- **Sessions without a final verifier have no verdict.** `Session.score()` on an environment with no `final_verifier_code` now returns `error_type='no_verifier'`, so `has_verdict` is false and trainers mask the episode. Before, it returned a plain 0.0 that read as a graded failure.
- **Harbor tasks:** `deepgym.harbor` reads Harbor task folders from a folder, a git URL or a Hugging Face dataset and runs each as a `HarborEnvironment` on any provider. The model's bash script runs as an unprivileged user with no network; a fresh sandbox from the same image grades a copy of its work directory, with `tests/` uploaded only then and the reward read from that sandbox, so a pre-written reward or a planted test runner scores nothing. Docker and Apple container build `environment/Dockerfile` tasks. `deepgym harbor import` validates (and with `--register`, registers) tasks, `deepgym qa` gates those with a `solution/solve.sh`, and `deepgym harbor export` writes environments as Harbor tasks with a separate offline verifier and a non-root agent. `TerminalBenchEnvironment` now loads and grades its tasks this way; before, it trusted a reward file the commands could write.
- **Console UI state:** starting runs navigates once, to the run or its eval; before, closing the dialog then replaced that with the runs page. Run, episode and environment views now clear when their selection changes instead of showing the previous one's data, and drop responses that arrive out of order, so a finished run no longer flips back to running while it polls. Episode replay shows a loading or error state for each frame's screenshot and draws the action marker only once that frame's image has loaded. "Run again" shows the API's error when the run is refused.
- **Infrastructure and verifier failures no longer read as model failures.** `eval()` now sets `error_type` on runs that raise (it dropped it, so they read as judged zeros), runs named environments without a verifier file, such as repo-patch tasks, instead of skipping them as unanswered, keeps suite order in both clients, and names each result in the new `EvalResult.env_names`. A provider failure while the verifier runs is a `SandboxError`, not a `VerifierError`. Docker, Apple, E2B, Modal and Daytona runs take the verdict from the verifier's stdout only, so a JSON line on stderr can no longer replace it, and keep stderr in `RunResult.stderr`. A step verifier that exits 2 or reports an `error_type` that isn't the model's fault now raises `VerifierError` and ends the episode, with no step reward (`step_rewards` is one shorter than `steps`), and `score()` then returns `error_type='verifier_error'`. `GymInfo` carries `error_type` and `has_verdict`. The verifier wrapper treats a return value that isn't a float, bool or dict, or a `passed` or `truncated` that isn't a real bool (`"false"` used to count as a pass; wrap numpy bools in `bool()`), as a verifier error (exit 2), and keeps a returned `truncated=True`. The console keeps no score for a run without a verdict, leaves it out of the score bins and counts it as an error; the CLI prints such runs as `ERROR (<error_type>)` with their cause (totals: see the next entry). `AsyncDeepGym` in HTTP mode sends a file-backed verifier's source inline, so built-in environments run remotely, and `max_parallel` below 1 raises `ValueError` in its `run_batch` and `eval` instead of hanging.
- **Judged totals next to the headline.** `BatchResult` and `EvalResult` keep their headline numbers conservative: `passed`, `failed`, `avg_score` and `pass_rate` count a run without a verdict as a failed 0, so a run that breaks its verifier or sandbox can only lower them. New fields sit beside them: `no_verdict_count`, `judged_count`, and the judged-only `judged_pass_rate` and `judged_mean_score`. A run without a verdict never counts as passed, even if it reported a pass. The console's mean score likewise counts a finished run without a verdict as 0 again (since the last change it left such runs out); its totals gain `judged_count`, `no_verdict_count` and `judged_mean_score`, and the runs page and environment health show a "No verdict" count with the judged pass rate and score beside the headline ones. The CLI prints the same, e.g. `Pass Rate: 62.00% (judged 70.00%, 12.00% no verdict)`. A session's final verifier now gives its verdict on stdout only, as the judges do, so a JSON line on stderr can no longer replace it, and its stderr is kept in `RunResult.stderr` on every backend.
- **Rewards in built-in envs, importers and CyberGym:** a built-in or imported verifier whose judge fails (a full disk, a broken library) now exits 2 with `error_type='runtime_error'`, so `has_verdict` is false; before, it printed an ordinary 0. `level_order_traversal` no longer builds nodes under missing parents, which marked a correct BFS wrong (18/25). `string_manipulation` drops an undocumented penalty that capped a correct split-and-slice answer at 0.3. `file_organizer`'s prompt names the `PROJECT_DIR` the verifier checks instead of `/tmp/project`. `data_pipeline` compares every written record, so altered ages or cities no longer pass. Log4Shell triage scores source IPs by exact overlap, so an invented IP costs credit, and both cyber envs score a non-object JSON answer instead of crashing. HumanEval and MBPP tests run against the dataset's own helpers and only the names the tests call, so a solution's own `range`, `set`, `encode_cyclic` or patched `math` can't rig the asserts; correct answers that skip the prompt's helper or the reference's first function now pass, and MBPP prompts name the functions the tests call. EvalPlus deep-copies each reference call, so a reference that mutates its arguments no longer corrupts the embedded inputs (Mbpp/635, Mbpp/734). EvalPlus and BigCodeBench pass only when every scored test passes and keep partial credit as the score; BigCodeBench counts a skipped test as a failure and a fully skipped suite as no verdict. The CyberGym runner scores what the patch changed on disk, not its text, and measures the reference the same way: changed lines outside a hunk and patches that change nothing score 0, paths outside the repository are refused, line endings and git-quoted file names survive, and the prompt names the `diff --git` format it checks. A qualified name like `other_benchmark/coin_change` no longer loads `coin_change` by its basename. CyberBench seed specs need finite weights in [0, 1] and write strict JSON, and `docs/cyberbench.md` drops the unsupported `--mode local`.
- **Trainer integrations keep failed runs out of training.** The TRL, Axolotl, DAPO and `RewardFunction` reward functions return `None` instead of 0.0 for a completion whose sandbox or verifier failed, so TRL 1.6+ leaves it out of its group's baseline and gives it no advantage, and every entry point now runs the last fenced code block (verl's batch `make_verl_reward_fn`, DAPO, `RewardFunction` and lm-eval used to run the raw text). `make_trl_reward_fn` takes `max_parallel` and `component`; the Axolotl and DAPO reward functions are TRL's, so Axolotl's now accept conversational completions. The verl single-turn agent loop drops a sample with no verdict under verl's v1 trainer (the default since 0.9), so its group's GRPO statistics come from the other samples, and masks it under the legacy trainer; the multi-turn loop does the same for a sandbox that fails to start or a final verifier that fails, which used to score a plain 0.0, and logs `error` in `reward_extra_info`. `make_lm_eval_task` now returns a task for `lm_eval.simple_evaluate` (lm-eval 0.4.9+) and replaces `register_deepgym_tasks`, which used a registry lm-eval no longer has; a verifier failure is left out of `deepgym_score` and `deepgym_pass` and shows in the new `deepgym_verdict`. `generate_axolotl_config(method='grpo')` now scores with `row_reward_fn`, which scores each `verl_rows` row with its own environment, and no longer takes `dataset_type`. The OpenRLHF reward endpoint runs in FastAPI's thread pool, so a slow verification no longer holds up other requests.
- **Hub environments round-trip.** `push_environment_to_hub` writes schema 2.0 rows that keep every `Environment` field (support files, verifier mode, case timeout, image, snapshot, name, type and the rest), refuses subclasses, and returns the commit it made; pushing over a schema 1.0 repo also rewrites the features its dataset card lists, which `push_to_hub` keeps and which would stop the new rows from loading. The loaders take `revision=` to pin that commit and warn when nothing is pinned. A Hub row is untrusted, so pushes and loads run one shared check: unknown fields, wrong types, a `verifier_path`, `env_vars`, a `verifier_mode` the verifier does not read as, and support file names that are not plain relative paths are all refused, and a custom `image` or `snapshot` loads only with `trust_image=True`. Schema 1.0 rows still load. `deepgym[hf]` needs datasets 2.16 or later.
- **API server lifecycle:** `deepgym serve` closes idle sessions on a 60-second sweep, without waiting for new traffic, and closes every session on shutdown. A session whose sandbox delete fails keeps its id and its slot: `DELETE` answers 502 and can be retried, and the sweep retries it too, up to 10 attempts; then its sandbox id is logged as an error, the slot is freed, and `/health` counts it in `leaked_sandboxes`. Providers now report a failed delete (`Sandbox.delete()` returns False; it still never raises, and a sandbox that is already gone counts as deleted) and `SandboxBackend.close()` raises on it; leaving a session's or trace's `with` block logs it as a warning instead, so `run_episode()` keeps its result and an exception from the block still propagates. Request bodies over 32 MiB get 413 before they are read. Async jobs count against the job limit only while queued or running, and their request bodies may take at most 256 MiB in all (429 above); a job is `queued` until a job thread is free, then `running`. Finished jobs stay readable up to the newest 10,000 or 256 MiB of results. A cancelled job stays cancelled: a queued one is dropped with its request, a cancelled batch starts none of its remaining outputs, and runs already going finish within their timeout with results dropped. All requests and jobs share one limit of 100 concurrent runs, so `max_parallel` no longer adds up across requests. Registering an environment takes the same fields as an inline run (`verifier_mode`, `case_timeout` and `support_files` were dropped), an invalid environment is a 422 before anything is queued (it was a 500, or a job stuck in `queued`), listings include each environment's `id`, and health, capabilities and the OpenAPI schema report the package version instead of 0.3.0. E2B commands are killed in the sandbox when they time out (E2B's own timeout only stopped waiting), and a solution call's deadline covers sending its request, so a solution that stops reading can't stall the verifier. `deepgym create` prints the environment with its `--name` and says it isn't saved. A release fails if its tag isn't the built version or the version is already on PyPI, and `scripts/publish.sh`, which could upload a wheel without the console, is gone.
- **Security: the Daytona desktop lockdown fails closed.** Every lockdown step must now take, and is checked twice: as the agent once applied (no terminal, IDLE, run dialog, panel, settings tool or "Open With" helper it can run, no Thunar custom-actions plugin it can load), and once the desktop runs — `xfce4-session` runs as the agent, x11vnc runs with only the flags Daytona starts it with and reads its no-remote, no-connect options from a file its own user can read, and a live query confirms remote control is actually off rather than trusting x11vnc’s argv; the probe ignores any rc file (`-norc`), and silence counts as off only once the query shows it went out over this display’s X property channel, so a probe that never ran, found no display, used another channel or timed out refuses the desktop. A missing helper, a desktop already running, or a session Daytona would start as its sudoer now raises `SandboxError`. The managed Chromium policy (DevTools off, `chrome://`, `file://` and the like blocked) is written, root-owned and not writable by the agent, to every dir a Chromium-family build reads (`/etc/chromium`, `/etc/opt/chrome`, `/etc/chromium-browser`), and `launch_app.sh` runs exactly the browser setup’s own PATH finds (`chromium`, then `chromium-browser`, then `google-chrome`), looked up as the agent so a folder only root can enter is skipped, and pinned by the lockdown so the launch is that binary; no binary is inspected. Before, `|| true`, `2>/dev/null` and unmatched globs skipped steps silently, and nothing checked whom the session ran as. Code a session verifier loads through `load_solution` now runs as `dgsolver` with its groups cleared, no-new-privs and an empty bounding set: sudo runs `setpriv` as root under a `visudo`-checked rule pinned to that exact drop, so a stray image group membership (a `shadow` line) and the image’s setuid binaries (`sudo`, `su`, `mount`, `chrome-sandbox`) no longer reach it. Before, that code kept its groups and ran without no-new-privs. Session setup proves each session user’s uid and primary gid are that account’s alone and its only group, and each harness directory (staging, verifier, runtime) is created through a helper that refuses a symlink or a redirected path and forces root ownership and mode (`mkdir -p -m` left a pre-existing one untouched); a work directory may no longer hold or sit in the runtime folder verifiers import from. Chromium drops `--test-type`, which only hid a warning bar kiosk mode never shows; `--no-sandbox` stays, with the reason in `launch_app.sh`: under the agent’s no-new-privs the setuid sandbox can’t start, and Daytona’s hosts deny user-namespace id maps to every non-root user.
- **Security: patches can't touch test infrastructure.** The SWE-bench Pro / MiMo patch runner only put back the paths the hidden test patch touches. A diff that added, for example, a repo-root `conftest.py`, a pytest plugin through `pytest.ini`/`setup.cfg`, a `.pth` or `sitecustomize.py`, a Go `TestMain`, or a jest/vitest config could make the test command exit 0 without fixing anything. Now every other path the diff touches, as listed by `git apply --numstat -z` forwards and reversed (raw, so quoted and non-ASCII names are matched as git writes them), is checked first. A diff that touches a test or its executable helpers, conftest/ini/runner config (including `tox.ini`, `tox.toml` and `go.work`), the pytest sections and `pytest11` entry points of `pyproject.toml`/`setup.cfg` and `[tool.tox]`, the test, runner and `workspaces` keys of `package.json`, Cargo's target, dev/build-dependency and workspace tables (`[workspace.package]` metadata aside), a `go.mod` added or removed below the repo root, build files that run code (`Makefile`, `pom.xml`, `build.gradle`, `build.rs`), or the installed harness (`node_modules`, `site-packages`, `vendor`, virtualenvs, `.cargo`), or that creates a symlink or a file mode other than 100644/100755, scores 0 with `error_type='test_infra_tampering'`. Config files are compared semantically and fail closed (a file that can't be parsed and shown unchanged counts as tampering). To avoid giving a correct fix a false zero, the rules deliberately do **not** refuse data fixtures under a test directory, other entry points such as `console_scripts`, an exec-bit flip on an ordinary file, dependency and version edits (Cargo `[dependencies]` and `[workspace.package]` metadata, and an existing `go.mod`, included), lockfiles including `go.sum`, or ordinary files that only share a word with a test name, such as `cmd/test.go` or `i18n.setup.ts` (checked over the 642 SWE-bench Pro gold patches: 12 refused (1.9%), real test files such as `*.spec.*`, `jest.setup.js` or `pytest.ini` plus Makefiles and a vendored dependency, which run code; a stubbed dependency is still caught by the stub package's own runner `bin`). That is a model fault, so verl trains on it instead of masking it. Every path is compared in one form, git's raw `-z` output through `normpath` with case kept. An edit the guard can't classify either way (a path with no such form inside the repo, a file the test command may name, by any normalized path its own path ends with, a folder it can't know such as `../` or `$VAR`, or its Python module, so only a word naming another folder outright is not a mention, or a `[workspace.package]` key outside the known metadata) still runs the tests: a failure is the normal, trained 0, so the edit gains nothing, and a pass, which the edit may have caused, gets `error_type='validation_uncertain'` with no verdict, so trainers mask it. If git times out listing the paths, the result is `error_type='validation_timeout'`, and if it can't find the repository top-level, `error_type='validation_error'`: no verdict either way, so trainers mask it. `deepgym qa` now runs a `patch_tampering` attack on self-contained patch tasks such as `mimo_code`. **This is a stopgap, not a complete defence.** A denylist of what a test runner loads can never be exhaustive, the config comparison knowingly reads only the keys above, and a diff to the code under test can still force an exit (`os._exit`/`atexit` at import) that the exit-code reward trusts. The real fix is a per-test report gate that takes the verdict from the test runner's own report (pytest/go/jest/vitest), written to a path the patch can't reach, and checks the hidden tests actually ran and passed; it lands in a follow-up and supersedes this denylist.

## 0.4.2 (2026-10-13)

- **Security: repo, terminal and cyber tasks no longer run on the host.** SWE-bench Pro, Terminal-Bench, CyberGym patch tasks and MiMo code tasks apply the model's patch or run its commands, then run tests, with no judge isolation. In `mode='local'` (and `auto` without Daytona) they used to do that on your machine; now they raise `SandboxError` and ask for `docker`, `apple`, `modal`, `e2b` or `daytona`. There is no opt-out. They also start their sandbox from the client's provider instead of always Daytona, and `scripts/run_cybergym_artifact_eval.py` drops `--mode local`.
- **Security: patches can't edit hidden tests.** The SWE-bench Pro patch runner used to apply the hidden test patch first and the model's diff after it. A diff could then still edit a hidden test file, for example through the source of a renamed test. Now the model's diff goes first. Every path the test patch touches, as listed by git's own parser (`git apply --numstat -z`, forwards and reversed), is put back to its state before the diff, and the test patch goes last. A diff that fails `git apply --check` still scores 0.
- **SWE-bench Pro: no stand-in tests.** A task with no test runner (no `test_commands`, and a language other than Python or JS/TS) now returns `error_type='unsupported_runner'` with score 0, so trainers mask it. Before, a `git diff --stat` stand-in exited 0 and a still-broken patch scored 1.0. A task with no tests no longer earns the 0.3 apply credit either, and the JS `npm install` step no longer counts as a passing test.
- **Patch extraction:** a diff whose last line is a blank context line (a single space) is no longer corrupted by whitespace stripping, which failed correct patches.
- **MiMo-V2.6-RL code tasks:** `scripts/import_mimo_rl.py` imports the 2,698 code tasks of `XiaomiMiMo/MiMo-V2.6-RL-oss` (Apache-2.0) as `mimo_code/<instance_id>` environments. Each is a `RepoPatchEnvironment`: its sandbox boots from the task's own image, the patch runner patches the repo in place, and the score is 1.0 if the test command exits 0, else 0.0. The cyber, general, webdev and music subsets aren't imported (see the README).
- **verl:** a patch that is malformed or doesn't apply (`invalid_patch`, `patch_apply_failed`) now scores 0 and is trained on instead of being masked out as a missing verdict, so models are penalised for broken patches.
- **Session reward integrity:** Daytona sessions now run through `SandboxBackend`, like every other provider: agent commands as `dgagent` in a loopback-only network namespace, verifiers as `dgverifier` from a root-only file. Before, the agent and verifier shared Daytona's passwordless sudoer, and the agent could reach Daytona's toolbox API on loopback, so it could forge any score. Desktop sessions run the whole xfce session and its apps as the agent and lock the desktop down before setup (no Thunar custom actions, "Open With" or custom-command launches, terminals, IDLE, or x11vnc remote control); setup scripts no longer get sudo, and Chromium runs with `--no-sandbox` as the unprivileged agent. Verifier scores only count after a clean exit (0, or 1 for a failed run): a verifier killed (e.g. exit 137) or crashing after printing a score is a `VerifierError`, never reward. Session verifiers can use `load_solution`/`run_solution` (locally, and where the image has sudo as a separate `dgsolver` user); the multi-turn `debug_fix` verifier now does, so an always-equal object no longer passes.
- **`api_request` env:** the verifier serves randomized slideshow documents, drawn from a fresh seed every run (reported as `seed`; one document always puts a decoy `title` before the answer and another after it, so printing the first or last title never gets full credit), from a local HTTP server and checks that the solution, run with each URL as `sys.argv[1]`, prints that document's `slideshow.title`. Before, it scored source keywords and output against a mocked response, so comments plus a fixed print scored 1.0 and passed the QA gate. The task now passes the URL as an argument and asks for the standard library only.
- **Loopback for solutions:** `run_solution(..., loopback_port=port)` lets the solution connect to a server the judge runs on `127.0.0.1:port` and nothing else: macOS allows that one port in the sandbox profile, and where the solution has its own network namespace (bwrap, sandbox users) a forwarder pipes the port through a Unix socket in a judge-owned directory the solution can enter but not change. In sandboxes the solution's offline namespace now has loopback up; root does that with `python -I -S` and a fixed `PATH`, so nothing in the solution's working directory or the environment can reach it.
- **Per-case scores:** a failed case without an explicit `score` now counts 0. Before, it got the passing default of 1.0, so `per_test_rewards` paid full credit for failed tests.
- **TRL:** the reward functions accept conversational completions (lists of message dicts, including tool-calling turns) and run the last fenced code block of the final assistant turn, like the verl adapter. Before, correct code scored 1 as plain text but 0 as a conversation, and fenced answers in plain text scored 0.
- **OpenRLHF:** the reward router accepts the payload OpenRLHF's agent client sends (`query`, `prompts`, `labels`), strips each prompt from its query and runs the response's last fenced code block. When OpenRLHF cut a long prompt's front tokens, the response starts after the prompt's tail; a query that doesn't contain its prompt scores 0 with `error_types` `prompt_mismatch`, so prompt text is never scored. Matching is linear in the text length, and requests are capped at 2M characters per text, 1024 samples and 64M characters in all (422 above). `outputs` still works. Before, OpenRLHF's requests were rejected with 422.
- **Code extraction:** `extract_code`, which the verl, TRL and OpenRLHF adapters and the QA difficulty probe share, drops end-of-turn tokens left at the end of a response (`<|im_end|>`, `<|endoftext|>`, `<|eot_id|>`, `</s>`, `<end_of_turn>`, ...). Before, valid unfenced code decoded with `skip_special_tokens=False` failed with a SyntaxError and scored 0.
- **Reward-hack attacks:** an attack whose run fails (timeout, sandbox or verifier error), whose result reports a verifier error (an `error_type` other than a model fault such as `invalid_patch`, or exit code 2, e.g. a verifier that raised inside the wrapper), or that never runs (LLM attack without a key or parseable exploits) is now `inconclusive` instead of counted as resisted. The rule is `RunResult.has_verdict`, which the verl reward's `error` flag now uses too, so it also masks exit-code-2 runs. `AdversarialReport` gains an `inconclusive` count, and `is_robust` is true only when every attack ran and none got through. `RewardAuditor` flags a verifier `exploitable` only when an exploit was found, and saved attack records carry an `inconclusive` flag. `ExploitDB.save` refuses an inconclusive record (no exploits, some attacks without a verdict, for example after a provider failure or without an Anthropic key) and returns False, so `RewardAuditor.audit(persist=True)` reports `stored=False` and `scripts/run_exploit_scan.py`, which now builds records the same way, tests that verifier again next time. Before, such audits were stored (the script even saved them as EXPLOITABLE) and later scans skipped them for good.
- **Quality gate:** every check and report has a `status`: `pass`, `fail`, `inconclusive` or `skip`, and `passed` is true only for `pass`. Multi-turn, computer-use and benchmark-backed environments are `skip` (neither passed nor failed) instead of passing; `hack_resistant` is `inconclusive` when no attack got through but some crashed; `stub_fails` is `skip` for a script reference. `deepgym qa` exits 0 when the checked environments pass, 1 if any fails, and 2 if none fails but some are inconclusive or none could be checked. The table and the console show the new statuses. Reports written by older versions don't load in the console; rerun `deepgym qa` to refresh them.

## 0.4.0 (2026-10-13)

- **Console:** `deepgym console` (alias `deepgym web`) serves a management UI and a JSON API under `/api`: searchable environments with task/verifier/reference views, background runs and small evals on any provider with per-case results, episode replay with screenshots, live Docker/Apple sandboxes with kill, and QA reports from `~/.deepgym/qa/`. Runs and episodes persist in `~/.deepgym/console.db`; `deepgym.console.record_episode(trajectory, result)` stores an episode from any agent loop. The API needs a per-launch token written into the served pages, refuses cross-origin writes and non-JSON bodies, and runs pasted solutions locally only with `--allow-local-exec`. Wheels ship the built UI. Replaces the single-page `deepgym web` debug UI (`deepgym.web` is removed).
- **verl masking:** `deepgym.integrations.verl_mask.DeepGymSingleTurnAgentLoop` scores single-turn rows itself and zeroes the response mask of samples whose sandbox or verifier failed (`error: 1.0`), so they get no gradient instead of training as a 0. A verl reward function or reward manager can't drop a sample.
- **Per-environment images:** set `image` on an `Environment`, a `MultiTurnEnvironment` or in `metadata.json` to boot its sandbox from that image. Docker, Apple container, Modal and Daytona pull it from a registry (a Daytona `snapshot` wins); E2B uses it as a template id. The image must run as root and have python3, bash, useradd and util-linux. The HTTP API refuses caller-chosen images.
- **Quality gate:** `deepgym qa [ENV ...] [--all]` checks single-turn environments before training: the reference solution scores 1.0 on every rerun, empty and stub solutions score below 1.0, and no heuristic reward-hack attack reaches the pass threshold. `--model` adds pass@1/pass@k from an OpenAI-compatible endpoint and flags tasks that are too easy or too hard. Writes one JSON report per environment to `~/.deepgym/qa/` and exits 1 if any environment fails. `--model` with `--mode local` or `auto` needs `--allow-local-exec`. All 26 built-in single-turn environments pass; the environment smoke test now runs the gate.
- **Reward-hack attacks** (`AdversarialTester`, `RewardAuditor`, the audit API) run through the `DeepGym` client they're given instead of always running locally, so a Daytona or container client runs them in its sandboxes.
- **Sandbox providers:** `mode='modal'`, `'e2b'` and `'docker'` join `'daytona'` and `'apple'` for single runs, `AsyncDeepGym` and shell sessions, all with the same isolation. Each provider is a folder in `deepgym/sandboxes/` implementing one small `Sandbox` protocol; Modal and E2B are optional extras. Judge runs fail closed when a sandbox can't cut the solution off the network. In sandbox sessions, verifiers run as their own user from a file the agent can't read, so leftover agent processes can't read or forge the score; agent and solver drops add no-new-privs; container sandboxes are capped at 2 CPUs, 2 GB and (Docker) 512 processes. `deepgym.apple_container` moved to `deepgym.sandboxes.apple`, `AppleContainerBackend` is now the provider-agnostic `SandboxBackend`, and `create_sandbox`/`cleanup_sandbox` moved to `deepgym.sandboxes.daytona`.
- **Apple container backend:** `DeepGym(mode='apple')` / `AsyncDeepGym(mode='apple')` run judges and multi-turn sessions in throwaway Linux VMs from Apple's `container` CLI on macOS. Same isolation as Daytona: the solution and session commands run as non-root users with all capabilities dropped and no network; a judge run fails rather than run online if the image lacks util-linux. Image set by `DEEPGYM_CONTAINER_IMAGE`. Desktop envs still need Daytona. On Daytona the solution now also runs without network when the sandbox allows it.
- **Rewards:** NaN, inf and out-of-range scores are verifier errors, never reward. A single run raises `InvalidScoreError`; batches and trainer reward functions score that sample 0 with `error_type='invalid_score'`. Non-finite reward components are zeroed. Before, NaN scored 1.0.
- **Benchmark-backed envs:** SWE-bench Pro, Terminal-Bench and `MixedEnvironment` now score correctly in `AsyncDeepGym` and in single sync runs. Before, both silently scored a 0.0 placeholder.
- **Benchmark names:** a fully qualified name such as `humaneval_plus/HumanEval_0` beats loose matches, and an ambiguous name raises instead of loading the wrong benchmark. Before, HumanEval+ requests could load HumanEval.
- **Isolation hardening:**
  - Local runs hide the home directory and every other run; only the Python install and the run's own directories are visible.
  - On Daytona the judge's temp files are private.
  - On macOS solutions can't fork unless `run_solution(..., allow_subprocess=True)`.
  - Scripts' leftover processes are killed when the script exits.
  - `cli_task` reads `.git` without running git.
  - `read_output` refuses symlinked paths.

- **Security: the solution no longer runs inside the judge.**
  - Before, single-turn verifiers imported the model's code into their own process, and in both local and Daytona mode it shared a folder with the verifier and test cases. It could print a fake score line, patch the verifier, read the expected answers, import the reference solution from the installed package, or return an object that equals everything.
  - Now verifiers call `load_solution()` / `run_solution()` from `deepgym_solution`, which run the solution in a separate isolated process:
    - Daytona: a dedicated Linux user.
    - Local: `sandbox-exec` (macOS) or `bwrap` (Linux), with the judge, the deepgym package and `~/.deepgym` hidden.
  - Only plain data crosses the boundary. All built-in verifiers and the HumanEval, MBPP and EvalPlus importers are migrated; re-run the import scripts for cached benchmarks.
  - BigCodeBench tests run with the solution inside the sandbox, because they need rich objects. That result is still forgeable by a determined model.
- Per-call `case_timeout` (default 10s), capped by the run's `timeout`: a slow case fails alone and the run returns partial credit instead of timing out.
- Verifier shape is detected by parsing the source (`script`, `verify_function`, `body`) or set with `verifier_mode`, replacing a text search that misclassified verifiers. `from __future__` imports are hoisted when wrapping.
- `support_files` on `Environment` (and `metadata.json`) for multi-file verifiers and shared helpers across environments.
- `cli_task` now works in its own directory (`my_repo` in the working dir) instead of a shared `/tmp/my_repo`.
- Breaking: `LocalExecutor.run()` / `AsyncLocalExecutor.run()` take a `JudgeJob`. `is_standalone_verifier`, `setup_sandbox` and `execute_verifier` are replaced by `prepare_verifier` and `run_judge_in_sandbox`.

- Added live multi-turn sessions (`dg.session()`, `dg.run_episode()`, `Session`): one sandbox per episode, actions applied step by step, final verifier run against the resulting state. Local and Daytona backends.
- Added real computer-use support on Daytona's desktop: typed GUI actions (click, type, key, scroll, drag, ...), full-resolution screenshots in observations, GUI-only action sets by default
- Added 5 computer-use environments (`signup_form`, `todo_list`, `settings_tabs`, `expense_sheet`, `file_manager`) with progress/guard verifiers and scripted reference runs checked live on Daytona
- Added 8 seeded variants per computer-use env (`load_environment(name, variant=i)`), each with a scripted reference run verified live
- Desktop lockdown during setup: Chromium devtools and `javascript:`/`chrome:`/`file:` URLs blocked, terminals and the run dialog disabled, file manager removed from browser tasks
- Added `/v1/sessions` HTTP endpoints (create, step, score, delete) with a race-safe session cap and 30-minute idle eviction
- Added verl multi-turn support: `DeepGymAgentLoop` (`agent_name: deepgym_agent`) keeps one sandbox per rollout, since verl's stock loop creates and releases tools per call, and sets `reward_score` from the final verifier; `DeepGymSessionTool` is its tool
- Verifiers in sessions run with `python -I` and are passed inline, never written to the sandbox, so the agent can't swap them or hijack them with planted modules
- Setup scripts that exit non-zero raise `SandboxError`; shell steps report `exit_code` in observation metadata; both backends run commands under bash
- Step verifiers that print garbage now raise `VerifierError` instead of scoring 0
- CI: ruff skips markdown task prompts and JSON payloads stored as `.py`, which formatting would change
- `ActionError` for actions the environment rejects (not allowed, unknown key name); the verl tool returns these to the model as text and raises everything else
- Sessions serialize concurrent step/score/close calls; a failed step verifier ends the episode with a consistent trajectory; step-verifier stderr is ignored
- `setup_timeout` (default 120s) bounds setup separately from per-step actions
- Daytona sessions create their work dir up front and tell command timeouts apart from connection timeouts via the SDK's typed errors
- `dg.eval()` and `AsyncDeepGym.run()` reject multi-turn envs with a clear error instead of crashing
- One shared `parse_verifier_output()` replaces five copies of verifier JSON parsing
- Daytona sessions wait for sandbox deletion before freeing an API slot, bound every desktop call with a request timeout, and delete sandboxes left behind by a failed create (found via a per-session label)
- Session API store is locked so idle eviction can't race a session that was just used
- Computer-use app state saves are atomic and applied in order (todo app chains its saves)
